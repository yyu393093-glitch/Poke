# 代码合入前检查清单（check 流程）

> **用途**：在 commit / push 前，对「前端 `src/`」或「后端 `server/`」新增/改动的模块做一遍标准化体检，确认能承接后续功能、且 Mac/Windows 通用。
> **来源**：沉淀自本项目的技术栈检查实践。共 8 项，每项给出适用端、命令、通过标准。

---

## 1. 配置一致性（路径别名 / 模块解析）

- **前端**：`vite.config` 的 `resolve.alias` 与 `tsconfig`/`jsconfig` 的 `paths` 是否一致；是否用了别名却没配。
- **后端**：ESM 相对导入是否一致；是否用 `import.meta.url` + `path.join` 定位文件，而非写死 `/Users/...`、`C:\...`、`/tmp`。

```bash
grep -rn "from ['\"]@/\|from ['\"]~/" src/        # 前端：找别名导入
grep -rn "/Users/\|C:\\\\\|/tmp" server/*.js       # 后端：找硬编码绝对路径
```

- **通过**：无「用了别名却未配置」；后端无硬编码绝对路径。

## 2. 环境变量

- 代码引用的每个 env 变量（`import.meta.env.*` / `process.env.*` / 自读 `.env`）是否都在 `.env.example` 里文档化。
- 真实 `.env` 是否被 `.gitignore` 忽略。

```bash
grep -rn "process\.env\|import\.meta\.env" src/ server/   # 找被引用的变量
git check-ignore .env server/.env                          # 确认真实 .env 不进 git
```

- **通过**：所有被引用变量都有 `.env.example` 模板；真实 `.env` 被忽略。

## 3. 冲突残留

```bash
grep -rn "<<<<<<<\|>>>>>>>" src/ server/
```

- ⚠️ `=======` 会误匹配注释里的 `// =====` 分隔线，命中后需人工确认。
- **通过**：无真实的 merge 冲突标记。

## 4. 导入路径 / 依赖

- `npm run build` 无 `Cannot find module`；新增依赖已 `install` 且进 `package.json` + lock。

```bash
npm run build 2>&1 | grep -iE "cannot find module|error"
for f in server/*.js; do node --check "$f"; done    # 后端语法 + 顶层 import 解析
```

- **通过**：build / 启动无缺模块、无缺依赖。

## 5. 文件大小写

```bash
git ls-files | sort -f | uniq -di
```

- **通过**：无仅大小写不同的重复文件（Mac/Windows 文件系统大小写不敏感，同名大小写不同会互相覆盖）。

## 6. 路由

- 无重复 path；**动态路由（`:id`）必须排在静态路由（如 `/list`）之后**，否则会被动态路由吞掉。

```bash
grep -rn "app\.\(get\|post\|put\|delete\)(\|path=\|<Route" src/ server/
```

- **通过**：无重复 path；静态路由定义在动态路由之前。

## 7. 公共行为不回归

- 确认没有改动既有组件/接口的默认行为，新增应是「加法」。

```bash
git diff HEAD~N -- src/components/          # 前端组件
git diff HEAD~N -- server/                  # 后端已有接口
```

- **通过**：已有组件/接口行为未变，只做加法。

## 8. 构建与启动

```bash
npm run build              # 前端构建
npm run dev                # 前端启动
npm --prefix server start  # 后端启动
curl -s localhost:3001/api/health   # 后端健康检查
```

- **通过**：前后端都能起，健康检查 200，控制台无报错。

---

## 附：Mac / Windows 通用性要点（每条都过一遍）

| 项 | 做法 |
|---|---|
| 换行 | `.gitattributes` 锁 `text=auto eol=lf`，避免 CRLF/LF 混用 |
| 文件路径 | 后端一律 `import.meta.url` + `path.join`，不手写 `\`/`/` |
| 命令 | 用 `npm --prefix server ...` 等跨平台形式，不写 shell 专有语法 |
| 读 `.env` | 解析时 `.split(/\r?\n/)` 兼容 CRLF |
| 时间/时钟 | 演示用**计数器**（如 17:57:00 起每秒 +1），不读 `new Date()`/系统时区 |
| 中文文件名 | 现代 Vite/git/Node 均支持 UTF-8 文件名，可保留 |
